为什么做它

资料不缺，缺的是能核对的答案

01

资料散

官方文档、PDF、实验笔记各在一处。关键词搜不全，路径、命令、错误码这类精确串尤其容易漏。

同一张表里做向量近邻 + IK 全文召回，RRF 融合。

02

AI 不可信

通用聊天机器人答得顺，但经常编，事后无法核对；技术文档里一个路径错了就白忙。

只把检索到的片段交给模型；没有合法引用就退回原文摘录。

03

每次都从头开始

上周读到哪、哪里没懂、喜欢多详细，没人记得，每次都要重新交代背景。

主题、目标、偏好、薄弱问题写入 PowerContext，重启后仍在。

怎么工作

一次提问，三次落库

  1. 1

    检索

    问题向量化后，seekdb 同时做 cosine_distance 向量召回与 MATCH ... AGAINST 全文召回，各取 30 条。

  2. 2

    作答

    RRF 融合取前 6 条交给本地模型；逐句校验 [n] 是否落在证据范围内，不合格就退回抽取式原文摘录。

  3. 3

    记住

    问答写入 queries，引用快照随笔记写入 notes；研究主题与进度交给 PowerContext。

两个数据库，两种记忆

seekdb 记资料，PowerContext 记人

seekdb：可引用的证据

同一张 chunks 表里同时建 HNSW 向量索引和 IK 全文索引，不做外部检索引擎。

-- 向量召回（余弦）
SELECT id, 1 - cosine_distance(embedding, %s) AS vec_sim
FROM chunks ORDER BY cosine_distance(embedding, %s) LIMIT 30;

-- 全文召回（IK 分词）
SELECT id, MATCH(text) AGAINST(%s IN NATURAL LANGUAGE MODE) AS ft_score
FROM chunks
WHERE MATCH(text) AGAINST(%s IN NATURAL LANGUAGE MODE)
ORDER BY ft_score DESC LIMIT 30;

两路各 30 条，RRF 1/(60+rank) 融合。中文技术文档里的路径与命令，靠全文路补足向量不敏感的部分。

PowerContext：可延续的学习

每个学习者一个 Scope（judian-learning），两类显式记忆，重启 Server 后仍在。

  • judian-profile研究主题、本周目标、回答详略偏好
  • judian-progress累计提问、上次问题、引用过的文档、薄弱主题
POST /v1/memory/remember        # 写入
POST /v1/memory/entries/list    # 读回

服务离线时写入 .runtime/memory_fallback.json，接口返回 source=local，界面如实标注「本地暂存」。
