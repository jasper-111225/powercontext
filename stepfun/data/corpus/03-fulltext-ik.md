# 全文索引与中文分词

全文检索解决的是“关键词匹配”问题：把文档切成词项，建立词项到文档的倒排表，查询时对词项求交并计算相关性。它和向量检索互补——向量擅长语义相近但用词不同的情况，全文擅长精确术语、编号、人名和代码符号。

seekdb 的全文索引通过 `FULLTEXT KEY ... WITH PARSER` 指定分词器。英文可以用空格分词，中文则需要专门的分词器：ngram 按固定长度滑窗切分，实现简单但会产生较多无意义词项；ik 基于词典和统计模型，能识别“向量数据库”“倒排索引”这类复合词，检索质量和索引体积都更均衡。

创建集合时可以指定全文分析器。使用 seekdb-js 时，configuration 里可以写：

```js
configuration: {
  hnsw: { dimension: 512, distance: "cosine" },
  fulltextConfig: { analyzer: "ik", properties: { ik_mode: "smart" } }
}
```

建表语句里会体现为 `FULLTEXT KEY idx_fts (document) WITH PARSER ik PARSER_PROPERTIES=(ik_mode="smart")`。如果运行环境没有启用 ik，SDK 会回退到 ngram，这时应在元数据里记录实际使用的分析器，避免评估时误判。

查询时，seekdb-js 的 `whereDocument: { $contains: "..." }` 会被转换成 query_string 查询。query_string 支持布尔运算符和通配符，因此用户输入要先做清洗：去掉引号、冒号、括号、加减号等特殊字符，否则一个多余的引号就可能让查询变成语法错误。清洗后仍然保留空格，让分词器自行处理。

中文检索的质量很大程度取决于分词粒度。以“向量检索”为例，ik 可能切成“向量 / 检索”，于是包含“全文检索”的文档也会命中“检索”。这是词法检索的固有特性，也是混合检索要引入向量一路的原因：RRF 会让两路都靠前的结果胜出，单一词项误匹配很难同时骗过两路。

全文索引同样需要刷新才能看到新写入的内容。批量导入时，把文档写入和索引刷新分开计时，可以清楚看到“写入耗时”和“可见性延迟”各自占多少。
