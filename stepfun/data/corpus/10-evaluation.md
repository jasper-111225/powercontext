# 检索质量评估方法

检索质量评估需要三样东西：固定的语料、带标注的查询集、明确的指标。语料固定后，每次实验的候选集合一致；查询集里每条查询标注相关文档；指标把排序结果换算成一个可比较的数字。

最常用的指标是 Recall@K。它衡量前 K 个结果里覆盖了多少相关文档，适合“不能漏”的场景。nDCG@K 考虑排序位置，越相关的文档排得越靠前得分越高，适合“排序质量”评估。MRR 只看第一个相关结果的名次，适合问答类单答案场景。三者一起看，能避免被单一指标误导。

做量化对比时，评测集必须完全相同，查询和文档的编码方式也要一致。比如查询统一加 BGE 指令前缀，文档不加；池化统一用 CLS；归一化统一开启。任何一处不一致，指标差异都可能来自流程而不是量化。

评估粒度也要说清楚。按文档评估时，先对同一文档的多个分块取最高分，再对文档排序；按分块评估时，直接对分块排序。前者更接近用户感知（用户关心哪篇文档相关），后者更适合调分块策略。本项目同时记录两种口径，主指标用文档级。

除了平均值，还要看最差情况。量化可能让少数查询的相关文档掉出前 K，平均值看不出这一点。报告里应给出指标的最小值、掉点查询列表，以及量化前后的排名变化。如果掉点集中在某类查询（例如包含数字或英文缩写的查询），可以针对性调整。

最后，评估脚本要可复现：语料和查询集入库，脚本一条命令跑完，输出 JSON 原始数据。技术说明里的表格应该由这份 JSON 生成，而不是手工填写。评审如果能自己跑一遍脚本并得到同样的数字，可信度会高很多。
