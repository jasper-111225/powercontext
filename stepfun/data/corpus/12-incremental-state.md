# 增量导入、集合与会话状态

知识库应用通常会经历多次导入：先导入一批笔记，过几天再补充论文，最后再导入会议记录。增量导入要求新数据能追加、旧数据不重复、检索结果始终对应当前知识库。

幂等键的设计是关键。分块 ID 用“文档内容哈希 + 分块序号”生成：同一篇文档重复导入时 ID 不变，upsert 会覆盖旧记录；文档内容修改后哈希变化，旧分块不会自动删除，需要额外的清理策略。对演示应用来说，覆盖已经足够；生产环境应记录文档版本，并在导入后删除同文档的过期分块。

集合（collection）是 seekdb 里组织和检索数据的单位。每个知识库对应一个集合，集合名带随机后缀避免冲突。集合里保存向量、原文和元数据，元数据包括文档名、分块序号、语言和字符数。查询时按集合隔离，切换知识库就是切换集合。

会话状态包括“当前选中的知识库”“最近一次查询”“界面上的计时数据”。这些状态可以放在 localStorage 和内存里，但要保证刷新页面后能恢复到一个一致的状态：如果记住的知识库已被删除，应自动回退到第一个可用集合，而不是继续向不存在的集合发查询。

连续操作容易出错的地方是竞态。用户在导入过程中切换知识库，导入任务仍在往旧集合写；用户在查询过程中删除集合，查询会报错。解决办法是让异步任务捕获开始时的集合 ID，完成后只在“仍然是当前集合”时更新界面；删除集合时取消或忽略进行中的请求。

检索结果的一致性还依赖索引刷新。导入完成后必须刷新，否则新分块查不到；刷新是异步语义，界面要等刷新返回后再提示“可检索”。如果导入和查询并发，应该让查询等待刷新完成，或者明确提示“索引合并中，结果可能不完整”。

最后，把所有状态变化记录到界面：当前集合、分块数、最后刷新时间、最近一次导入耗时。用户和评审都能一眼看出数据是不是最新的。
