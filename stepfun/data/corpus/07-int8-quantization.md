# ONNX INT8 动态量化

量化是把浮点权重映射到低比特整数的过程。对 Transformer 来说，权重占模型体积的绝大部分，把 FP32 权重换成 INT8，理论上体积可以降到四分之一。实际文件还会包含缩放因子、零点和非量化算子，因此压缩比略低于 4。

ONNX Runtime 提供动态量化（dynamic quantization）。它只量化权重，激活值在推理时根据实际数值动态计算缩放因子。优点是校准简单，不需要代表性数据集；缺点是推理时多了一点计算量。对本项目这种“权重远大于激活”的小模型，动态量化是性价比最高的选择。

动态量化的关键参数是权重类型和是否逐通道。权重类型选 QUInt8（无符号 8 位整数）通常比 QInt8 更稳，因为激活和权重的零点分布更自然。逐通道（per-channel）为每个输出通道单独计算缩放因子，精度明显优于逐张量。实测中，QInt8 逐通道且不缩小范围时，句向量余弦相似度会降到 0.84，而 QUInt8 逐通道可以保持 0.994，这说明量化配置不能照抄，必须实测。

量化的产物仍然是标准 ONNX 文件，浏览器不需要额外的反量化代码。ONNX Runtime Web 的 WASM 后端支持 MatMulInteger 等量化算子，Transformers.js 通过 dtype 选择文件名：fp32 对应 model.onnx，fp16 对应 model_fp16.onnx，int8 对应 model_int8.onnx，q8 对应 model_quantized.onnx。

评估量化不能只看困惑度或单句相似度，还要看检索指标。推荐做法是固定一份带标注的查询集，分别在 FP32 和 INT8 模型上跑 Recall@K、nDCG@K 和 MRR，报告变化幅度。句向量余弦相似度适合做冒烟检查，检索指标才反映真实影响。

模型体积要按同一口径统计：只统计实际下载的 ONNX 权重文件，不要把分词器、配置文件和运行时 wasm 算进去。压缩比等于 FP32 体积除以量化后体积。本项目 FP32 为 94.9MB，INT8 为 24.0MB，压缩比 3.95 倍。
