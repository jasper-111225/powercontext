# 技术说明（一页版）

**作品**：seekdb × 端侧 AI 推理 —— 浏览器本地 embedding + seekdb 向量/全文混合检索的迷你知识库（StepFun 赛道）

## 1. 模型与量化

| 项目 | 内容 |
|---|---|
| 模型 | `BAAI/bge-small-zh-v1.5`，ONNX 转换版 `Xenova/bge-small-zh-v1.5`（ModelScope 镜像同仓库），512 维，CLS 池化 + L2 归一化 |
| 量化方案 | ONNX Runtime **动态量化**：权重 **QUInt8**、**逐通道**，激活运行时动态计算；FP32 输入输出不变 |
| 体积 | FP32 **94.85 MB** → INT8 **24.01 MB**，压缩比 **3.95×** |
| 数值保真 | 6 句对照：句向量余弦均值 **0.9941**、最小 0.9929、最大绝对误差 0.0178 |
| 检索质量 | 20 条标注查询 / 14 篇 / 49 块，文档级：FP32 R@5 **0.925**、nDCG@5 **0.906**、MRR **0.975**；INT8 R@5 **0.925**、nDCG@5 **0.909**、MRR **0.975**（差异在噪声内） |

- 复现：`npm run model:fetch` → `npm run model:quantize` → `npm run eval`，原始数据在 `evidence/model-quantization.json`、`evidence/quality-report.json`。
- 查询指令前缀做过消融：官方前缀在自然语言问句上使 nDCG@5 由 0.906 降到 0.879，因此默认不加，配置项保留。

## 2. 端侧运行

- 运行时：`@huggingface/transformers@3.8.1` + ONNX Runtime Web 1.22，模型与分词器全部本地静态资源，**运行时不访问任何模型仓库或云端推理**。
- 推理在 Web Worker 中执行，主线程只做 UI；文档与查询共用同一模型、同一池化与归一化。
- 后端选择：**WebGPU 优先** → 自动降级 **WASM**。`?backend=webgpu|wasm` 可强制验证；自动模式会跳过 SwiftShader / llvmpipe 软件适配器（本机实测其比 WASM 慢 7 倍），并在界面说明原因。
- 界面明确展示当前后端、dtype、适配器、模型加载与预热耗时、WASM 线程数；降级时顶部黄色提示条。
- WASM 多线程依赖跨源隔离：服务端和 Vite 均发送 `Cross-Origin-Opener-Policy: same-origin` 与 `Cross-Origin-Embedder-Policy: require-corp`。
- 验证：无头 Edge 156 上分别强制 WASM 与 WebGPU，完成「导入 49 块 → 检索 → 基准」全流程；两端结果均返回 `DBMS_HYBRID_SEARCH` 排名。

## 3. seekdb 使用

- 接入：`seekdb-js@1.4.0`，server 模式连接 `127.0.0.1:2881`；首次启动自动建库 `stepfun_kb`，每个知识库一个集合 `kb_<8位随机>`。
- 表结构（实测 `SHOW CREATE TABLE`）：`VECTOR(512)` + HNSW cosine 向量索引、`FULLTEXT ... WITH PARSER ik` 全文索引、JSON 元数据、`_id` 主键；DDL 见 `evidence/schema.txt`。
- 混合检索：一次 `collection.hybridSearch({ query: { whereDocument: { $contains } }, knn: { queryEmbeddings }, rank: { rrf: { rankConstant: 60 } }, nResults })`；数据库内完成两路召回 + RRF，客户端不拼合。全文参数先清理 `" : ( ) + -` 等 query_string 特殊字符。
- 写入与刷新：按 100 条一批 `upsert`，导入结束调用一次 `refresh_index()`；页面分别显示写入与刷新耗时，刷新后才提示可检索。
- 增量与状态：分块 ID 为内容哈希 + 序号，重复导入幂等覆盖；知识库切换只改当前集合，异步任务写回开始时的集合，删除集合后自动回退。

## 4. 状态与优化

| 配置 | 模型体积 | 冷 → 热加载 | 49 块向量化 | 查询向量化 P50 | seekdb 检索 P50 | 端到端 P50 |
|---|---:|---:|---:|---:|---:|---:|
| FP32 + WASM（基线） | 94.85 MB | 41.8 s → 5.0 s | 13.39 s | 94.2 ms | 54.7 ms | 158.6 ms |
| **INT8 + WASM（自动）** | **24.01 MB** | **20.0 s → 1.25 s** | **10.87 s** | **38.1 ms** | **53.7 ms** | **89.6 ms** |
| INT8 + WebGPU（SwiftShader） | 24.01 MB | 24.5 s → 1.30 s | 156.15 s | 507.6 ms | 19.6 ms | 526.8 ms |

（5 条查询 × 3 轮中位数；本机 WebGPU 为软件渲染，不代表硬件 GPU；完整报告见 `docs/性能与质量报告.md`。）

- 批处理：按长度排序 + token 预算分批（8–16 块）。A/B 显示在本语料上与固定 batch=8 差异在噪声内（8.54 vs 7.15 块/秒），不宣称加速；保留它是为了减少长度差异大时的 padding。
- 其他优化：模型文件本地 + HTTP 缓存、Worker 隔离、加载后预热一次、查询只编码一次、TopK 与 RRF 候选窗口受控、单次 DB 往返。
- 计时口径：查询向量化（Worker 推理）/ seekdb 检索（服务端一次 hybridSearch 往返）/ 端到端（点击到渲染）。
- 说明：本机 WebGPU 为 SwiftShader 软件渲染，WebGPU 行不代表硬件 GPU 性能；自动模式因此选择 WASM。复现命令 `npm run bench`。
