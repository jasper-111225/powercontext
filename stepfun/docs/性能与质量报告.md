# 性能与质量实测报告

> 所有数字来自本仓库脚本在提交版本上的实际运行，原始数据在 `evidence/`。
> 机器是共享的 4 核开发机，存在后台负载，冷启动波动较大；报告同时给出热加载与多次重复的中位数。

## 1. 测试环境

| 项 | 值 |
|---|---|
| CPU / 内存 | Intel(R) Core Ultra 7 258V / 4 vCPU / 9.7 GB（共享机器） |
| OS / 内核 | Ubuntu 22.04 / 6.8.0 |
| 浏览器 | Microsoft Edge 156（HeadlessChrome/156，WebGPU 走 SwiftShader 软件适配器） |
| 数据库 | seekdb `5.7.25-OceanBase seekdb-v1.4.0.0`，server 模式 `127.0.0.1:2881` |
| 模型 | `Xenova/bge-small-zh-v1.5` ONNX：FP32 94.85 MB / INT8 24.02 MB |
| 语料 | 14 篇示例文档 / 49 块 / 15,098 字符 |
| 查询集 | 20 条标注查询（评测）；5 条固定查询 × 3 轮（性能） |
| 推理后端 | WebGPU（SwiftShader）、WASM 4 线程 + SIMD，均开启 COOP/COEP |
| 批大小 | INT8：8–16 块（长度感知分批）；FP32：同策略 |

## 2. 方法与口径

- **固定条件**：同一设备/浏览器/语料/查询集/模型版本；对比某一项时其他条件不变。
- **模型体积**：只统计实际下载的 ONNX 权重文件（不含分词器与运行时 wasm）。
- **压缩比**：`FP32 体积 / INT8 体积`。
- **质量**：文档级排序指标。同一文档的多个分块取最高分，再对文档排序；查询与文档分别编码，CLS 池化 + L2 归一化。
- **分阶段计时**：
  - 模型加载：Worker 内从 `pipeline()` 开始到可推理；
  - 文档向量化：49 块的 Worker 推理总时长（不含写库）；
  - 写入 / 刷新：服务端 `upsert` 与 `refresh_index()`；
  - 查询向量化：Worker 内单条查询推理；
  - seekdb 检索：服务端一次 `hybridSearch` 往返（含 RPC 与结果序列化）；
  - 端到端：点击检索 → 结果可渲染。
- **重复**：性能取 5 条查询 × 3 轮的中位数与 P95；模型加载区分冷启动与同 profile 刷新后的热加载。
- **降级验证**：分别用 `?backend=wasm` 与 `?backend=webgpu` 强制两条路径，均完成导入→检索全流程。

## 3. 量化结果

| 指标 | FP32 | INT8 | 变化 |
|---|---:|---:|---:|
| 权重文件体积 | 94,851,877 B（94.85 MB） | 24,020,718 B（24.02 MB） | **3.95×** |
| 6 句对照余弦均值 | 1.0 | **0.9941** | -0.0059 |
| 6 句对照余弦最小 | 1.0 | 0.9929 | -0.0071 |
| 最大绝对误差 | 0 | 0.0178 | — |

量化方式：ONNX Runtime `quantize_dynamic`，权重 **QUInt8**、**逐通道**、激活动态。逐通道与 QUInt8 的选择来自实测对照：

| 变体 | 体积 | 句向量余弦均值（10 句对照） |
|---|---:|---:|
| 官方 pre-quantized int8 | 23.9 MB | 0.9655 |
| QUInt8 逐张量 | 23.9 MB | 0.9817 |
| **QUInt8 逐通道（采用）** | **24.0 MB** | **0.9943** |
| QInt8 逐通道（未缩小范围） | 24.0 MB | 0.8407（异常掉点，弃用） |
| QInt8 逐通道 + reduce_range | 24.0 MB | 0.9932 |

## 4. 检索质量

评测集：14 篇文档、49 块、20 条中文/英文查询，每条标注 1–2 篇相关文档。

| 模型 | R@1 | R@5 | R@10 | nDCG@5 | nDCG@10 | MRR |
|---|---:|---:|---:|---:|---:|---:|
| FP32 | 0.775 | 0.925 | 1.000 | 0.906 | 0.934 | 0.975 |
| INT8 | 0.775 | 0.925 | 1.000 | 0.909 | 0.937 | 0.975 |
| 差值 | 0 | 0 | 0 | +0.003 | +0.003 | 0 |

结论：在本评测集上，INT8 与 FP32 的 Recall 和 MRR 完全一致，nDCG 差异小于 1 个百分点，属于评测集噪声。

**查询前缀消融**（BGE 官方建议给查询加指令）：

| 方案 | R@5 | nDCG@5 |
|---|---:|---:|
| 不加前缀（采用） | 0.925 | 0.906 |
| 加「为这个句子生成表示以用于检索相关文章：」 | 0.925 | 0.879 |

本应用的查询是自然语言问句，前缀反而让排序变差，因此默认不加；配置项保留，可复现该实验。

## 5. 浏览器性能

### 5.1 主表

| 配置 | 模型体积 | 冷加载 → 热加载 | 49 块向量化 | 查询向量化 P50 | seekdb 检索 P50 | 端到端 P50 | P95 |
|---|---:|---:|---:|---:|---:|---:|---:|
| FP32 + WASM（基线） | 94.85 MB | 41.8 s → 5.0 s | 13.39 s（3.66 块/秒） | 94.2 ms | 54.7 ms | 158.6 ms | 212.6 ms |
| **INT8 + WASM（自动模式采用）** | **24.02 MB** | **20.0 s → 1.25 s** | **10.87 s（4.51 块/秒）** | **38.1 ms** | **53.7 ms** | **89.6 ms** | **136.9 ms** |
| INT8 + WebGPU（SwiftShader 软件渲染） | 24.02 MB | 24.5 s → 1.30 s | 156.15 s（0.31 块/秒） | 507.6 ms | 19.6 ms | 526.8 ms | 1417 ms |

- 查询与检索耗时是 15 次查询（5 条 × 3 轮）的中位数；数据库检索只占端到端的一小部分。
- 冷加载受共享机器负载影响很大：同一 INT8+WASM 配置在不同时段观察到 6.7 s / 20 s / 78 s；热加载稳定在 1.25 s 左右。
- INT8 相对 FP32：模型小 3.95×、冷加载约快 2×、查询向量化快 2.5×、端到端快 1.8×，检索质量不变。
- WebGPU 行使用 **SwiftShader 软件适配器**，不代表硬件 GPU；其文档向量化比 WASM 慢 14×，这也是自动模式跳过软件适配器的依据。`?backend=webgpu` 仍可强制验证该路径。

### 5.2 写入与索引刷新（INT8 + WASM）

| 阶段 | 耗时 |
|---|---:|
| 分块（14 篇） | 12–36 ms |
| 本地向量化（49 块） | 10.87 s |
| 写入 seekdb（批量 upsert） | 0.99 s |
| 刷新索引 | 0.55 s |
| 端到端导入 | 12.47 s |

写入与刷新合计约 1.5 s，占导入总时间约 12%；一次导入只刷新一次索引，而不是每批刷新。

### 5.3 批处理 A/B（同一页面、同一模型、24 块）

| 策略 | 中位数 | 吞吐 |
|---|---:|---:|
| 固定 batch=8 | 2.81 s | 8.54 块/秒 |
| 长度排序 + token 预算（默认） | 3.36 s | 7.15 块/秒 |

在这份长度较均匀的语料上，两种策略差异被机器噪声淹没（单轮波动 1.9–3.7 s），**没有证据表明 token 分批更快**。保留它是为了在长度差异大的真实文档上减少 padding；本报告不据此宣称加速。原始数据：`evidence/batch-ab.json`。

## 6. 降级与状态验证

| 检查 | 结果 |
|---|---|
| WebGPU 可用（软件适配器） | `?backend=webgpu` 成功加载并完成检索；界面徽章 WebGPU |
| WebGPU 不可用 / 软件适配器 | 自动模式选择 WASM；顶部黄色提示；徽章「WASM 降级」；运行面板给出跳过原因 |
| 强制 WASM | `?backend=wasm` 全流程通过 |
| 跨源隔离 | `crossOriginIsolated=true`，WASM 线程 4 |
| 索引刷新可见性 | 导入后立即检索到新增 49 块 |
| 增量/幂等 | 同一文档重复导入 upsert，不产生重复分块 |
| 集合切换 | 检索始终针对当前集合；异步导入写回开始时的集合 |

## 8. 复现

```bash
# 应用
npm install && npm run build && npm start

# 质量
npm run corpus && npm run eval

# 浏览器性能（需另开终端先启动应用）
npm run bench                    # INT8: wasm + webgpu
EMBED_DTYPE=fp32 npm run bench   # FP32 基线（需先把 model.onnx 放到 web/public/models/.../onnx/）

# 批处理 A/B / 示例库截图
node scripts/batch-ab.mjs
node scripts/seed-demo.mjs
```
